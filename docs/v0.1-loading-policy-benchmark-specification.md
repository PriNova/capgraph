# V0.1 Graph Loading-Policy Benchmark

## 1. Purpose

V0 remains the historical baseline. Its specification, report, and raw records are unchanged.

V0.1 isolates two possible causes of the V0 Graph overhead:

1. metadata traversal and graph-tool overhead;
2. repeated one-skill-at-a-time loading and context replay.

This benchmark can report Flat, Graph Progressive, Graph Batch, or no meaningful difference as the best observed result. It must not infer statistical significance from this pilot.

## 2. Fixed Task

Every run uses this exact prompt:

```text
Create a physics-enabled cube named CapgraphBenchmarkCube in UPBGE.

Known root capability:
physics-object-create

Complete the task and verify the result. Stop after verification passes or you determine that completion is impossible.
```

Root resolution is not tested.

## 3. Composition-Leak Control

The `physics-object-create` Markdown body describes capability purpose, inputs, output, state semantics, caveats, and completion criteria. It does not list its dependency recipe or implementation scripts.

CapGraph frontmatter remains the composition source of truth:

```yaml
capgraph-requires: "object-create rigid-body-add collision-add"
capgraph-verify-with: "physics-object-verify"
```

The Flat fixture is generated from the same source files. Fixture generation removes CapGraph metadata only. An automated regression test compares every source and generated Markdown body for exact content equality.

## 4. Conditions

### Flat

- Normal flat skill discovery exposes all five names and descriptions.
- The agent loads complete generated `SKILL.md` files with `read`.
- `skill_graph` is unavailable.

### Graph Progressive

- Normal skill discovery does not expose graph-managed capabilities.
- `expand("physics-object-create")` returns metadata only.
- The agent uses individual `load(skill)` calls.
- Batch loading is a protocol failure.

### Graph Batch

- Uses the same graph metadata and source skill bodies as Graph Progressive.
- `expand("physics-object-create")` returns metadata only.
- One `load_many("physics-object-create")` call returns the deterministic execution closure and declared verification bodies.
- Individual graph loading or multiple batch calls are protocol failures.
- Recovery bodies are not returned.

`load_many` returns exact, unsummarized bodies in separate objects. Execution and verification are separate result arrays. Oversized output causes an explicit tool error; it is never silently truncated.

## 5. Deterministic Closure

Required capabilities use dependency-first topological order with deduplication. The root follows its dependencies. Verification remains terminal and logically separate:

```text
Execution:
object-create
rigid-body-add
collision-add
physics-object-create

Verification:
physics-object-verify
```

`expand` remains metadata-only. No recovery capability is loaded unless a relevant failure occurs.

## 6. Controlled Configuration

Defaults match V0:

- model: `openai-codex/gpt-5.6-luna`;
- reasoning: `max`;
- fresh in-memory session per run;
- same task prompt;
- same UPBGE extension and operation interface;
- same initial empty scene;
- no compaction or automatic retry;
- no human steering;
- independent verification outside the model session.

The condition-specific difference is capability discovery and loading policy only.

## 7. Balanced Schedule

The schedule uses all six permutations of the three conditions. Each condition runs six times, appears twice in each position, and precedes and follows every other condition equally across blocks.

| Block | Position 1 | Position 2 | Position 3 |
|---:|---|---|---|
| 1 | Flat | Graph Progressive | Graph Batch |
| 2 | Graph Progressive | Graph Batch | Flat |
| 3 | Graph Batch | Flat | Graph Progressive |
| 4 | Flat | Graph Batch | Graph Progressive |
| 5 | Graph Batch | Graph Progressive | Flat |
| 6 | Graph Progressive | Flat | Graph Batch |

The runner records block, position, and global sequence.

## 8. Protocol

A Graph run must expand the known root before prose loading and before the first UPBGE mutation.

Graph Progressive must load the root with an individual `load` call and must not call `load_many`.

Graph Batch must call `load_many` exactly once after expansion and before mutation. It must not use individual graph loads.

Independent scene success does not override a protocol failure.

## 9. Measurements

Record separately for every attempt:

- independent verified success;
- turns;
- agent tool calls and failed tool calls;
- duration;
- provider input and output tokens;
- cache reads and writes when available;
- provider cost;
- skill catalog bytes;
- graph metadata bytes;
- loaded skill prose/result bytes;
- complete operation sequence;
- exact skills loaded;
- `expand` call count;
- graph load call count;
- loading policy (`none`, `progressive`, or `batch`);
- number of skill bodies returned;
- scene reset policy (`manual` or `reserved_object`).

Keep byte categories separate from provider token usage. Do not claim exact token attribution from byte measurements.

## 10. Limits and Verification

Use V0 limits:

- 5-minute maximum duration;
- 12 agent tool calls;
- clean-scene gate;
- no steering or repair during a run.

The default gate is manual. With `--auto-reset`, the harness removes only the exact reserved object `CapgraphBenchmarkCube` before each run. It also removes that object's mesh only when the mesh has no remaining users. It verifies that the reserved object is absent afterward. Reset operations happen before measured duration starts and are not exposed to the model. No other object, data-block, or scene setting is changed.

Use a dedicated benchmark scene. Automated reserved-object deletion does not restore unrelated scene changes.

After the model stops, the harness calls `verify_physics_object` outside model context. Success requires `ok: true` with no failures.

Infrastructure failures are recorded and repeated in the same schedule slot. Task, protocol, tool, and infrastructure failures remain distinct.

## 11. Runner and Report

Run:

```bash
npm run benchmark:loading-policy
```

Enable the narrow automatic reset with:

```bash
npm run benchmark:loading-policy -- --auto-reset
```

Raw records go to ignored JSON Lines files under `benchmarks/results/` unless `--output` is supplied.

Produce a report only from completed raw records. Report counts and medians for each condition, every failure, exact loading sequences, and limitations. A missing or unavailable UPBGE environment is not benchmark evidence and must not be converted into a result.
